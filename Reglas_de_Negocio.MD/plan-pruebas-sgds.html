Cómo construir una prueba nueva

Tu proyecto tests/SGDS.Application.Tests ya está listo para correr — solo referencia SGDS.Application, así que hoy puede probar directamente los Helpers (calculadoras) sin tocar nada más.

  1. Un archivo por clase que pruebas. Crea CalculadoraXxxTests.cs junto a UnitTest1.cs (puedes renombrar ese archivo — su nombre no importa para xUnit, solo el de la clase).
  2. Patrón AAA (Arrange / Act / Assert), igual que tu prueba existente: // Arrange var config = new ConfiguracionEstampillas(); var entrada = new CalculadoraEstampillas.Entrada( ValorContratoBruto: 100_000_000m, IncluyeIva: false, TarifaIva: 0, TipoEntidad: CalculadoraEstampillas.TipoEntidadGobernacion, RegimenContratista: CalculadoraEstampillas.RegimenDeclaranteRenta, TipoContrato: CalculadoraEstampillas.TipoContratoObra, FuenteRecursos: CalculadoraEstampillas.FuenteRecursosPropios, Municipio: "Bucaramanga"); // Act var resultado = CalculadoraEstampillas.Calcular(entrada, config); // Assert Assert.Equal(2_000_000m, resultado.Items.Single(i => i.Nombre == "Pro-Hospital").Valor);
  3. Un caso por variante → [Theory] + [InlineData], como ya haces con ObtenerValorPorAnio. Úsalo para tablas de decisión (categoría → tarifa, año → valor, tipo → mínimo), y [Fact] para casos únicos (una excepción, un flujo puntual).
  4. Excepciones esperadas: Assert.Throws<ArgumentException>(() => CalculadoraEstampillas.Validar(entradaInvalida));
  5. Corre todo con dotnet test tests/SGDS.Application.Tests desde la raíz del repo.
  6. Actualización: las reglas de Comfenalco (CalcularCategoriaCarne, Validar) ya se movieron a SGDS.Application/Helpers/ReglasComfenalco.cs — mismo patrón que CalculadoraEstampillas — así que hoy se prueban directo, sin reflexión ni referenciar SGDS.Api. El controller solo resuelve el TipoSolicitud por id y delega. Lo único que sigue quedando fuera de SGDS.Application.Tests son las pruebas de integración de los Controllers (auto-asignación, listado restringido, la cadena GoTrace→Infoconsumo→SycTrace) — esas sí necesitan Microsoft.EntityFrameworkCore.InMemory + un ClaimsPrincipal de prueba.
  7. Frontend (SGDS.Frontend/src/config/*.ts): no hay corredor de pruebas unitarias todavía — solo tests/example.spec.ts de Playwright (E2E, sin instalar como dependencia del proyecto todavía). Para probar funciones puras como calcularCuotaCredito o calcularCategoriaCarne del lado del frontend haría falta instalar vitest.
